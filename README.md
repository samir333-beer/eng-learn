# Ingich — приложение для изучения английского

Мобильное приложение для изучения английских фраз с интервальным повторением.
Клиент — React Native (Expo), сервер — FastAPI. Регистрация по email с кодом
подтверждения, вход по паролю, по одноразовому коду и через Google.

## Возможности

### Учётная запись

- Регистрация в три шага: email → код из письма → имя и пароль
- Вход по паролю и по одноразовому коду из письма
- Вход через Google (OAuth 2.0, токен проверяется на сервере)
- Сброс пароля по коду из письма
- Сохранение сессии между запусками приложения

### Обучение

- **284 фразы** четырёх уровней: A1 (77), A2 (62), B1 (80), B2 (65)
- **31 тема**: приветствия, еда, путешествия, работа, здоровье, эмоции и др.
- Фильтр по уровню и теме
- Озвучка фразы на английском (text-to-speech)
- Интервальное повторение по системе Лейтнера: 6 боксов с интервалами
  0 → 1 → 3 → 7 → 14 → 30 дней
- Ежедневная сессия: до 20 карточек на повторение и до 10 новых

### Прогресс и статистика

- Профиль со статистикой: изучено фраз, серия дней, прогресс по уровням
- Таблица лидеров по изученным словам и по времени обучения
- Учёт времени, проведённого в приложении

### Экраны

| Экран | Назначение |
|---|---|
| Обучение | Карточка дня, быстрый переход к повторению |
| Карточки | Словарь с фильтрами по уровню и теме |
| Профиль | Статистика, прогресс по уровням, выход |
| Повторение | Сессия интервального повторения |
| Лидеры | Рейтинг пользователей |
| Вход / Регистрация / Сброс пароля | Экраны авторизации, регистрация в 3 шага |

## Архитектура

```
Телефон (Expo Go)                    FastAPI
React Native + expo-router   ──►     routers → services
        │                              │
        │ HTTP/JSON + JWT              ▼
        │                          SQLAlchemy ORM
        │                              │
        │                              ▼
        │                       SQLite / PostgreSQL
        │
        └──► Gmail SMTP (коды) и Google OAuth (вход)
```

Клиент не содержит бизнес-логики: проверка кодов, выдача токенов и подсчёт
интервалов повторения выполняются на сервере.

## Технологии

**Клиент**

- Expo SDK 54, React Native 0.81, React 19
- expo-router (файловая навигация)
- react-native-reanimated (анимации), expo-haptics (тактильный отклик)
- expo-secure-store (хранение токена), expo-speech (озвучка)
- TypeScript 5.9

**Сервер**

- FastAPI 0.115, Uvicorn
- SQLAlchemy 2.0 (SQLite в разработке, PostgreSQL в Docker)
- python-jose (JWT), bcrypt (пароли)
- slowapi (rate limiting)
- google-auth (проверка Google ID Token)
- pytest (тесты)

## Запуск

### 1. Сервер

```powershell
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python main.py
```

Сервер поднимется на `http://0.0.0.0:8000`, документация — `/docs`.
Перед запуском заполните `.env` (см. таблицу переменных ниже).

### 2. Клиент

```powershell
cd frontend
npm install
copy .env.example .env
npm run dev
```

Скрипт `npm run dev` запускает сервер и Expo одновременно, определяет
локальный IP компьютера и прописывает его в `.env`, затем показывает QR-код.

Альтернатива — два терминала:

```powershell
# терминал 1
cd backend
python main.py

# терминал 2
cd frontend
npx expo start
```

### 3. Телефон

Установить **Expo Go**, подключить телефон к той же Wi-Fi сети, что и
компьютер, отсканировать QR-код. Либо нажать `w` для запуска в браузере.

### Переменные окружения

`backend/.env`

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | ключ подписи JWT (обязателен в production) |
| `DATABASE_URL` | строка подключения к БД |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | срок жизни токена (по умолчанию 7 дней) |
| `CODE_EXPIRE_MINUTES` | срок жизни кода из письма |
| `SMTP_EMAIL`, `SMTP_APP_PASSWORD` | Gmail и пароль приложения |
| `GOOGLE_*_CLIENT_ID` | идентификаторы Google OAuth |
| `CORS_ORIGINS` | разрешённые источники |
| `APP_ENV` | `development` или `production` |

`frontend/.env`

| Переменная | Назначение |
|---|---|
| `EXPO_PUBLIC_API_URL` | адрес сервера, например `http://192.168.0.10:8000` |
| `EXPO_PUBLIC_GOOGLE_*_CLIENT_ID` | идентификаторы Google OAuth |

Без настроенного SMTP в режиме `development` код подтверждения печатается
в лог сервера — можно тестировать без почты.

### Docker

```powershell
cd backend
docker compose up --build
```

Поднимает PostgreSQL 16 и API с ожиданием готовности базы.

## API

`Authorization: Bearer <token>`.

| POST | `/auth/forgot-password` | запросить код сброса |
| POST | `/auth/reset-password` | установить новый пароль |
| GET | `/auth/me` | профиль текущего пользователя |

## Инженерные решения

**Пароли.** bcrypt с солью, а не хэш без соли: при утечке базы восстановить
пароль перебором нереально.

**Коды подтверждения.** В базе хранится только SHA-256 хэш кода. Код
одноразовый: успешная регистрация помечает запись использованной, а запрос
нового кода инвалидирует предыдущие. Срок жизни ограничен.

**Защита от подбора кода.** После 5 неверных попыток код блокируется до
запроса нового — ответ `429`. Вход в аккаунт по 6 цифрам без этого
ограничения взламывается за минуты.

**Rate limiting.** `slowapi` на чувствительных эндпоинтах: 5 запросов кода
в минуту, 20 попыток входа в минуту, 30 проверок кода в минуту.

**JWT.** Подпись HS256, срок жизни 7 дней, идентификатор пользователя
в поле `sub`. В production сервер отказывается стартовать с дефолтным
`SECRET_KEY` — защита от выкладки конфигурации разработчика.

**Google OAuth.** ID Token проверяется на сервере через `google-auth`
с проверкой audience. Вход нельзя подделать, даже изменив код клиента.

**Ответ одним запросом.** Эндпоинты входа возвращают токен и профиль сразу,
поэтому вход стоит одного сетевого запроса, а не двух.

**Интервальное повторение.** Алгоритм Лейтнера: правильный ответ повышает
бокс карточки, ошибка сбрасывает в нулевой. Интервалы 1, 3, 7, 14, 30 дней.
Это проверенная методика, а не случайная выдача карточек.

**Производительность клиента.** Экраны под новым замораживаются
(`freezeOnBlur`), анимации идут только через `transform` и `opacity`
на UI-потоке, фоновые градиенты статичны. Переход между шагами регистрации
разнесён по кадрам, чтобы не было рывка на слабых устройствах.

**Доступность.** Поле ввода кода озвучивается скринридером: «Код
подтверждения, введено N из 6». Декоративные ячейки скрыты от TalkBack
и VoiceOver.

## Тесты

```powershell
cd backend
python -m pytest tests/ -q
```

Покрыты проверка кодов, защита от подбора, границы сроков действия и
логика интервального повторения. 13 тестов, все проходят.

## Структура проекта

```
eng-learn/
├── backend/
│   ├── api/
│   │   ├── routes/          # auth, phrases, progress, quiz, srs, leaderboard
│   │   └── deps.py          # получение текущего пользователя из JWT
│   ├── core/                # конфигурация, JWT, хэширование кодов
│   ├── data/phrases/        # каталог 284 фраз по уровням
│   ├── db/                  # подключение и инициализация БД
│   ├── models/              # ORM-модели
│   ├── schemas/             # Pydantic-схемы запросов и ответов
│   ├── services/            # бизнес-логика
│   ├── tests/               # pytest
│   ├── Dockerfile
│   ├── docker-compose.yml
│   └── main.py
└── frontend/
    ├── app/
    │   ├── (auth)/          # вход, регистрация, сброс пароля
    │   └── (tabs)/          # обучение, карточки, профиль, повторение
    ├── components/          # переиспользуемые компоненты
    ├── constants/           # палитра, адрес API
    ├── context/             # AuthContext
    ├── hooks/               # валидация, коды, таймеры, клавиатура
    ├── lib/api/             # клиент HTTP и запросы
    └── scripts/start-dev.js # единый запуск сервера и Expo
```
